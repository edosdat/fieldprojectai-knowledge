## Contenu de la base de connaissances

### F01 — Philosophie & structure d'un projet
Bulldozair n'est pas un outil libre ou un bloc-notes numérique. C'est un outil de procédure, de suivi, de preuve et de reporting. Tout projet Bulldozair doit être conçu à partir du reporting final. Les 3 piliers sont : la tâche (unité minimale), le workflow (évolution de la tâche), le reporting (finalité du projet).

### F02 — Règle 1 espace = 1 usage
C'est la règle la plus importante. Chaque espace Bulldozair doit être monofonction. Ne jamais mélanger Suivi de chantier, OPR, FNC, CRR, Audit/QSE dans le même espace.

### F03 — Limites techniques
Limites observées sur le terrain : 5 000 tâches maximum par espace, 20 utilisateurs maximum par espace. Au-delà, créer des espaces séparés.

### F04 — Attribution vs Partage
Attribution = responsabilité directe (À:). Partage = visibilité sans responsabilité (CC:). Un utilisateur non attribué et non en partage ne voit pas la tâche.

### F05 — Rôles utilisateurs
5 rôles : Propriétaire (1 seul), Admin (1-2 max), Collaborateur, Rapporteur, Lecteur. L'email est l'identifiant unique obligatoire. Les entreprises = toujours Rapporteur, jamais Collaborateur.

### F05b — Groupes Bulldozair
Groupe interne MOE pour le partage par défaut. Groupe entreprise pour l'attribution par lot. Créer le groupe interne MOE EN PREMIER.

### F06 — Structure interne d'une tâche
1 tâche = 1 observation = 1 ligne dans les rapports. Contenu : photos, commentaires, position, formulaire. Métadonnées : tags, statut, attribution, partage, dates.

### F07 — Tags — familles officielles
Suivi de chantier : Nature / Zone / Activité. OPR : Zone / Activité (Nature INTERDIT). FNC : Type FNC / Zone / Activité / Criticité. CRR : Section / Sous-section. QSE : Nature QSE / Zone / Gravité. INTERDIT : 0 tag, nom d'entreprise comme Activité.

### F08 — Statuts & Workflows — valeurs figées
Limite technique : 16 statuts max. Recommandation : 5-6 statuts. Suivi : À faire → À valider → Refusé → Terminé. OPR : À lever → À valider (MOA) → Refusée → Terminée. CRR : Nouveau → En cours → Terminé. FNC : Ouverte → En analyse → En traitement → À valider → Close → Clôture documentaire. QSE : Constat → À traiter → À valider → Terminé.

### F09 — Formulaires
Utiliser pour : checklists normées, plans de contrôle, audits. Ne PAS utiliser pour : OPR, CRR, observations simples, forte volumétrie. Règle : moins de 20 champs, plusieurs petits formulaires plutôt qu'un énorme.

### F10 — Plans, modèles 3D et SIG
3 supports : Plan 2D (PDF), Fond de carte SIG (GeoJSON), Modèle 3D (IFC/BIM). Bulldozair supporte nativement les fichiers IFC. Navigation 3D sur tablette. DWG non supporté — exporter en PDF.

### F11 — Reporting
Tout ce qui n'existe pas dans les tâches n'existera pas dans le rapport. Types : fiche de visite, rapport OPR, FNC, CRR, rapport photo, export CSV, Word custom, Excel custom.

### F12 — Suivi de chantier
70% des projets. Tags : Nature / Zone / Activité. Workflow : À faire → À valider → Refusé → Terminé. INTERDITS : Nouveau, En cours, En attente.

### F13 — OPR
Tags : Zone / Activité. INTERDIT : famille Nature. Workflow : À lever → À valider (MOA) → Refusée → Terminée. 1 tâche = 1 réserve. Formulaire INTERDIT.

### F14 — FNC
Tags : Type FNC / Zone / Activité / Criticité. Workflow 6 statuts : Ouverte → En analyse → En traitement → À valider → Close → Clôture documentaire.

### F15 — CRR
CRR = Compte Rendu de Réunion. Tags : Section / Sous-section. Workflow : Nouveau → En cours → Terminé. 1 tâche = 1 point d'action. Attribution et date d'échéance obligatoires.

### F16 — QSE / Audit
Tags : Nature QSE / Zone / Gravité. Workflow : Constat → À traiter → À valider → Terminé. INTERDITS : Nouveau, En cours, Résolu, Clôturé.

### F17 — SIG Infrastructure
Pour routes, rails, réseaux, VRD étendus. Support : GeoJSON WGS84 < 15 Mo. 1 tâche = 1 point singulier (PK, défaut, constat).

### F18 — Méthode Éloi — 15 étapes
1.Contexte 2.Cas d'usage 3.Reporting (CRITIQUE) 4.Découpage espaces 5.Tags 6.Statuts 7.Formulaires 8.Équipe 9.Partage par défaut 10.Plans/3D/SIG 11.Template 12.Tâche exemple 13.Rapport exemple 14.Formation 15.Suivi post-démarrage.

### F19 — Découpage des espaces
Split obligatoire si : ≥5000 tâches, ≥20 utilisateurs, 2 cas d'usage différents. Ne jamais mettre dans le même espace : Suivi+OPR, FNC+CRR.

### F20 — Template projet
Le template DOIT contenir : tags, statuts, groupe partage par défaut. NE DOIT PAS contenir : plans, formulaires, tâches. Un template par cas d'usage.

### F21 — Formation utilisateurs
2 formations distinctes : collecte terrain (collaborateurs/rapporteurs) et configuration (chefs de projet/admins). Suivi post-démarrage 1-3 semaines obligatoire.

### F22 — Anti-pattern : Absence de tags
Cause n°1 d'échec. Symptômes : impossible de filtrer, rapports vides. Solution : minimum 2 familles de tags, template avec tags pré-créés.

### F23 — Anti-pattern : Tâches fourre-tout
1 tâche = 1 observation = 1 responsable = 1 statut = 1 ligne dans le rapport. Jamais plusieurs observations dans une seule tâche.

### F24 — Anti-pattern : Statuts & workflow
AP3: pas de statuts utilisés. AP4: absence d'attribution. AP5: espace trop large. AP6: workflow trop complexe. AP7: mauvaise gestion des plans.

### F25 — Anti-pattern : Utilisateurs & formulaires
AP8: trop d'utilisateurs. AP9: pas de partage par défaut. AP10: formulaires trop longs. AP11: pas de template projet.

### F26 — Checklist démarrage
Valider avant tout déploiement : cas d'usage, rapport, volumétrie, découpage, tags, workflow, équipe, partage par défaut, supports, template, tâche exemple, rapport exemple, formations.

### F27 — Checklist tags
Au moins 2 familles. Tags courts et lisibles. Pas de doublons. Pas de tags fourre-tout. L'activité ≠ nom d'entreprise.

### F28 — Checklist tâches
1 observation unique, 1 photo minimum, commentaire précis, position sur plan, tags, statut, attribution, date d'échéance.

### F29 — Arbres décisionnels
Aide à choisir : cas d'usage, workflow, besoin de formulaires, découpage en espaces.

### F30 — 10 règles essentielles
1.Définir le rapport d'abord. 2.1 espace=1 cas d'usage. 3.Tags=colonne vertébrale. 4.Workflow simple 4-6 statuts. 5.1 tâche=1 observation. 6.20 utilisateurs max. 7.5000 tâches max. 8.Partage par défaut obligatoire. 9.Plans superposables avant remplacement. 10.Template obligatoire avant démarrage.
